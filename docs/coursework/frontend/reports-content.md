# ОТЧЁТ 2 ПРОЕКТИРОВАНИЕ ИНТЕРФЕЙСА

Цель этапа — определить навигацию, визуальную тему и правила адаптивности. Я использовал светлый фон, тёмно-зелёный текст, лимонный акцент и локальный Manrope. Основная кнопка ведёт в конструктор. Карточки сохраняют одинаковую последовательность сведений: фото, тип, модель, стоимость упаковки, наличие при проверке и действия.

Публичный layout объединяет header, основную область и footer. Для закрытых действий добавлены сообщения с переходом к входу. Модальные окна используют native dialog, заголовок, кнопку закрытия и возврат фокуса. Формы имеют связанные подписи, ограничения длины и понятный текст ошибок.

На узком экране навигация переносится, конструктор становится одноколоночным, административные таблицы прокручиваются внутри контейнера. Декоративная схема клавиатуры уменьшается. Проверка на 390×844 выявила выход 3D проекции за ширину страницы; он устранён ограничением сцены.

# ОТЧЁТ 3 СОСТОЯНИЕ И АВТОРИЗАЦИЯ

Цель этапа — объединить страницы общим состоянием и подключить реальный вход. Context содержит текущего пользователя, черновик, каталог, загрузку и уведомления. Reducer описывает изменения состояния. При запуске auth/me восстанавливает пользователя по токену, если он существует в sessionStorage.

Черновик сохраняется в localStorage независимо от авторизации. При смене пользователя привязка к чужому buildId удаляется. Сохранённые списки находятся в MySQL и доступны только владельцу. Страница /builder?id=... показывает загрузку до получения данных, чтобы старый черновик не перезаписал другой список.

# ОТЧЁТ 5 АНИМАЦИЯ GSAP

Цель этапа — добавить интерактивность, связанную с темой проекта. Применены официальные навыки greensock/gsap-skills: базовые анимации, timelines, React, ScrollTrigger и производительность. Библиотека GSAP установлена локально через npm, внешняя CDN загрузка во время работы не требуется.

В Hero используется useGSAP с областью ref. Заголовок и кнопки появляются с небольшим сдвигом, клавиши — последовательно. Кнопка разбирает схему по слоям через timeline и contextSafe. Параллакс указателя ограничен точным указателем и широким экраном. В Reveal карточки появляются при прокрутке через ScrollTrigger.

Очистка удаляет GSAP контексты и события. Для prefers-reduced-motion входные эффекты отключены, разбор выполняется без длительного движения. Используются transform и autoAlpha. Позиционирование схемы не меняет расчёт товаров и не мешает формам.

Вывод: реализовано больше трёх дополнительных элементов интерактивности. Их назначение связано с объяснением комплектности и навигацией. Ветви reduced motion проверены по коду; отдельный ручной прогон с системной настройкой не заявляется.

# ОТЧЁТ 6 АДМИНИСТРАТИВНОЕ SPA И ИИ

Административная часть включает обзор, комплектующие, предложения, заказы и пользователей. В обзоре отображаются статистика учебного склада и число реальных предложений. Формы комплектующих поддерживают создание и изменение, проверяют JSON объект характеристик, цену и остаток. Удаление требует отдельного подтверждения.

В браузере создан демонстрационный корпус#13 с ценой 1000 ₸, затем цена изменена на 1250 ₸. При JSON массиве вместо объекта форма показала ошибку. Окно удаления проверено с отменой. В учебном заказе#1 статус изменён с нового на подтверждённый; таблица и карточка отразили результат.

[FIGURE admin-overview.jpg | Рисунок 4 — Обзор панели управления]

ИИ-помощник связан с настоящим серверным Groq. После проверки ответа сервер пересчитывает стоимость по своему каталогу. Модель не получает email или токен пользователя. Для модели цены передаются в тенге, а публичный API хранит денежные суммы в тиынах. Неизвестные товары и превышение бюджета отклоняются.

В первом фактическом запросе с бюджетом 150000 ₸ получены GMMK PRO Black Slate, Gateron Red и GPBT Black Ash за 121448 ₸. После расширения каталога при бюджете 90000 ₸ получены GMMK 2 65% Black, HyperX Red и Black Ash за 78717 ₸. Один запрос получил 503 после HTTP 400 Groq; повтор завершился успешно. Субъективное описание ИИ может содержать неточности; цена и комплектность берутся из проверенного расчёта.

Вывод: пять разделов SPA работают с API, а ИИ не заменяет проверку денежных сумм и идентификаторов. При 503 пользователь может продолжить ручной выбор.

# ОТЧЁТ 7 ТЕСТИРОВАНИЕ И ПЕРЕДАЧА РЕЗУЛЬТАТА

Проверка выполнялась 18.11.2026 на отдельной локальной базе keycraft_frontend. Серверная suite завершилась успешно: 73 теста и 469 утверждений. После изменения денежных единиц запроса к модели повторно прошли 8 тестов RetailRecommendationTest с 22 утверждениями. Они используют Http::fake и не расходуют внешний API.

Клиент Next.js прошёл 6 тестов HTTP-модуля, ESLint, TypeScript и производственную сборку. OpenAPI сверён с 44 реальными операциями без ошибок. Audit production зависимостей без dev вернул 0 уязвимостей. Полный audit содержит 14 high записей цепочки инструментов разработки вокруг picomatch; опубликованного исправления на дату проверки нет. Это ограничение не скрыто в протоколе.

Ручной прогон включал навигацию, поиск, фильтр Белого Ветра, пустые результаты, карточку, расчёт упаковок, перезагрузку черновика, сохранение и изменение сборки, настоящий Groq, пять административных разделов и два размера экрана. В консоли проверенного браузерного сеанса ошибок не зафиксировано. Это не заменяет тестирование на всех физических устройствах.

Подготовлены исходники с содержательными коммитами, README, скрипт запуска, OpenAPI и локальная Postman коллекция, пояснительная записка, настоящие скриншоты, презентация и речь. Действующие секреты, базы и node_modules не включаются в архив. Документация остаётся локальной; сдача в Classroom не выполнялась.
