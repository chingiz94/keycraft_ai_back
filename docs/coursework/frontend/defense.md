Меня зовут Алимканов Жасулан. Я представляю пользовательский интерфейс конструктора механических клавиатур KeyCraft AI. Моя задача — помочь человеку подобрать настоящие комплектующие, посчитать достаточное количество упаковок и перейти к покупке у продавца.

Для реализации я выбрал Next.js с App Router, React Context и reducer для состояния, Tailwind CSS и GSAP. В проекте есть публичная главная, каталог и описание сервиса. Покупатель может собрать черновик без регистрации, затем войти и сохранить список в аккаунте. Администратор работает в отдельном SPA из пяти разделов.

Готовый Laravel backend по исходному распределению разработан Нукушевым Чингизом. Я использую его авторизацию, роли, CRUD и складские заказы. Для нового интерфейса добавлены розничный каталог, расчёт упаковок и сохранение списка реальных товаров. Розничная покупка и учебный склад не смешиваются: список не создаёт заказ в Белом Ветре и не списывает деньги.

Каталог содержит 20 моделей и 27 предложений Белого Ветра, Vendara и Over-Shop. У каждого предложения есть конкретный URL, цена и время проверки. Снимок проверен 18 ноября 2026 года. В магазине пользователь уточняет наличие в своём городе, доставку и окончательную стоимость.

В основе GMMK PRO уже установлены корпус, плата, плейт и стабилизаторы. Поэтому пользователь выбирает основу, свитчи и кейкапы. ANSI версия имеет 82 позиции для свитчей. Упаковка Red содержит 120 штук, достаточно одной. Для Lynx по 36 нужно три упаковки, останется 26 свитчей. Сервер пересчитывает стоимость по каталогу и не принимает цену от браузера.

Состояние пользователя и черновик объединены Context. Токен находится в sessionStorage, черновик — в localStorage, а сохранённая сборка — в MySQL. При 401 сессия очищается. При загрузке сохранённого списка форма ждёт ответ API, чтобы старые данные не перезаписали другой выбор.

GSAP отвечает за появление заголовка и клавиш, разбор схемы по слоям, параллакс и появление карточек при прокрутке. useGSAP и contextSafe связывают анимации с компонентом, cleanup удаляет обработчики. При reduced motion длительные эффекты отключаются. Интерфейс проверен при 1440×900 и 390×844.

ИИ-помощник использует настоящий Groq. Модель получает бюджет и доступный каталог, выбирает ID, а сервер проверяет категории, совместимость и сумму. После расширения каталога получены GMMK 2 65% Black, две упаковки HyperX Red и Black Ash за 78 717 ₸ при бюджете 90 000 ₸. Один запрос получил 503 после HTTP 400 провайдера, повтор завершился успешно. Если ИИ недоступен, приложение показывает ошибку и оставляет ручной выбор.

Административное SPA включает обзор, комплектующие, предложения, заказы и пользователей. Создание и изменение компонента, ошибки JSON и смена статуса учебного заказа проверены через интерфейс. Права повторно проверяются сервером, поэтому скрытая ссылка сама по себе не служит защитой.

Сервер прошёл 73 теста с 469 утверждениями, HTTP-клиент —6 тестов. Проверки типов, ESLint, сборка и сверка 44 операций API завершились успешно. Ограничения и известные предупреждения dev зависимостей указаны в протоколе. Подготовлены исходники, инструкции, пояснительная записка, отчёты и презентация. Сейчас я покажу работающие сценарии.

## Порядок демонстрации

1. Открыть http://localhost:5173, нажать разбор/сборку клавиатуры.
2. Каталог: найти GPBT, выбрать магазин Белый Ветер, включить наличие и открыть Black Ash. Показать пять основ и поиск HyperX.
3. Конструктор: GMMK PRO + Lynx36 + Black Ash, объяснить 3 упаковки и 155174 ₸; заменить на Red, показать 121448 ₸.
4. Войти buyer, сохранить список, открыть из «Мои сборки», изменить название. Пароль вводить без показа .env.
5. ИИ: бюджет 90000 ₸, пожелание «Компактная основа 65%, HyperX Red, тёмные кейкапы», получить подбор или показать обработанную 503 и продолжить вручную.
6. Войти admin, показать пять разделов, форму компонента и учебный заказ. Не понижать последнего администратора и не удалять записи во время защиты.
7. Показать мобильный размер и локальную документацию /docs. Ссылку магазина можно открыть для просмотра, покупку не оформлять.

## Ответы на вероятные вопросы

**Почему три категории вместо шести?** Реальный barebones включает четыре внутренних части. Повторная покупка этих частей была бы ошибкой. Старый шеститипный склад сохранён для отдельного сценария backend.

**Зачем Context?** В задании обязателен менеджер состояния. Context и reducer связывают сессию, каталог, черновик и уведомления между страницами; локальные фильтры остаются в своей странице.

**Где подтверждён заказ Белого Ветра?** В проекте нет такой операции. Список открывает карточку магазина, заказ оформляется пользователем у продавца.

**Можно ли подменить цену в запросе?** Нет. API принимает ID, сверяет категории и пересчитывает цену. price и total в розничном запросе запрещены.

**Всегда ли работает ИИ?** Нет, возможны квота или сетевой отказ. При 503 пользователь видит сообщение, его черновик сохраняется. Автоматического вызова другого платного провайдера нет.

**Что ещё проверить перед реальным развёртыванием?** Обновление карточек продавцов, согласованный способ получения цен, физические устройства, эксплуатационное окружение и исправленные версии инструментальных зависимостей.
