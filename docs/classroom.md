## Что можно проверить преподавателю

1. Установить проект по README в отдельную MySQL базу и выполнить миграции.
2. Задать локальные демонстрационные пароли, выполнить CourseworkSeeder.
3. Импортировать `docs/KeyCraft.postman_collection.json` в Postman. Пароли и токены в экспортируемой коллекции пустые; заполнить их локально.
4. Проверить вход, запрет чужих данных, CRUD, совместимость, оформление/повтор/отмену заказа.
5. Выполнить `php artisan test` и `npm run test:client`. На момент доработки: 56 PHP-тестов / 309 утверждений и 6 клиентских тестов. Повторный прогон Postman описан в [протоколе](testing.md), он создаёт свои фикстуры только на выделенном локальном стенде. Проверки ИИ используют контролируемые ответы без расходов провайдера.
6. Для реального ИИ создать собственный ключ Groq Free, настроить `.env` по `docs/ai.md` и выполнить подбор. Успешную работу Groq пользователь подтвердил в локальной среде; проверка этого аккаунта не воспроизводится в GitHub без его ключа.

Проверки конкурентности InnoDB и наблюдаемой локальной нагрузки описаны в `docs/verification.md`. Замер нагрузки на строго ограниченной машине 2 CPU / 4 ГБ отдельно не выполнялся.

## Границы сдачи

Документация Postman не опубликована по открытой ссылке по выбору пользователя. Доступны локальный HTML, OpenAPI и переносимая коллекция. Приватный GitHub содержит исходники и материалы; доступ преподавателю владелец выдаёт отдельно.

Интеграционный клиент из этого репозитория проверен. Совместная приёмка с отдельным фронтендом партнёра, согласование темы и подписей преподавателем, сама защита и отправка файлов в Classroom не выполнялись. Оплата, доставка и автопарсинг маркетплейсов исключены из первой версии по ТЗ.
