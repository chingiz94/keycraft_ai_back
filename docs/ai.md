# Настройка настоящего ИИ-подбора

Сервис `RecommendationService` вызывает OpenAI Responses API по адресу `https://api.openai.com/v1/responses`. Локального генератора рекомендаций и подмены ответа модели нет.

## Подключение

В серверном `.env` задайте:

```dotenv
OPENAI_API_KEY=your_server_api_key
OPENAI_MODEL=gpt-4.1-mini
```

Укажите собственный действующий ключ; пример выше не является ключом. Модель настраивается через `OPENAI_MODEL` и должна поддерживать Responses API и Structured Outputs. После изменения `.env` выполните `php artisan config:clear` либо пересоздайте конфигурационный кеш при развёртывании. Ключ хранится только на сервере и не должен попадать в Git, Postman, браузер или фронтенд.

## Запрос и результат

Покупатель отправляет `POST /api/v1/ai/recommendations` с Bearer-токеном Sanctum и JSON:

```json
{
  "budget": 10000000,
  "format": "65",
  "preferences": "Тихая клавиатура для работы, линейные свитчи"
}
```

Деньги указаны целыми тиынами KZT: `10000000` соответствует 100 000 тенге. Пожелания ограничены 1000 символами. Лимит — 10 запросов в минуту на пользователя, включая неудачные запросы. Таймаут внешнего вызова — 30 секунд, соединения — 5 секунд; автоматических платных повторов нет.

Модели передаются только бюджет, формат, пожелания и доступные детали каталога: ID, название, тип, формат, цена, остаток и характеристики. Email, пароль и токен пользователя в payload не включаются. Поэтому в свободном тексте пожеланий также не следует указывать личные данные. Для запроса устанавливается `store: false`.

Ответ модели запрашивается по строгой JSON Schema: массив `items` с `component_id` и `quantity`, а также `explanation`. Сервер проверяет типы данных, повторяющиеся и выдуманные ID, принадлежность ID переданному каталогу, количества, остатки, комплектность, совместимость и бюджет. После внешнего вызова детали повторно считываются из БД, чтобы учесть изменение каталога за время ожидания. Итог вычисляет сервер из текущих цен.

При успехе ответ `200` содержит `data.items`, `data.explanation`, `data.total` и `data.compatibility`. Сборка автоматически не сохраняется; клиент может предложить пользователю сохранить выбранный состав через API сборок. Наличие деталей при подборе не резервируется: окончательная проверка и списание выполняются при оформлении заказа.

## Коды ошибок

| Код | Причина |
| --- | --- |
| 401 | Не передан действующий токен |
| 403 | Роль не даёт доступа к подбору |
| 422 | Неверные параметры, нет доступных деталей, подбор несовместим или превышает бюджет, каталог изменился |
| 429 | Превышены 10 запросов в минуту |
| 503 | Нет ключа, провайдер недоступен, таймаут, неполный ответ, отказ модели или некорректные данные ответа |

Сырые ошибки провайдера и секреты пользователю не возвращаются.

## Проверка

`php artisan test --filter=RecommendationTest` проверяет настоящий HTTP-контракт приложения с подставленными ответами провайдера (`Http::fake`): корректный ответ, приватность payload, проверку каталога после ожидания, несовместимость, бюджет, наличие, неизвестные и повторяющиеся ID, сетевую ошибку, отказ и неполный JSON, отсутствие ключа, а также ограничение частоты запросов. Эти тесты не расходуют средства API.

Во время подготовки проекта реальный платный вызов OpenAI не выполнялся. Приёмка реальной интеграции требует настроенного ключа и отдельного запроса к этому эндпоинту с доступным совместимым каталогом.

Формат внешнего запроса основан на [официальной документации Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses).
