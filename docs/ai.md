# Настройка настоящего ИИ-подбора

Сервис `RecommendationService` вызывает Responses API выбранного провайдера: Groq (`https://api.groq.com/openai/v1/responses`) или OpenAI (`https://api.openai.com/v1/responses`). Локального генератора рекомендаций и подмены ответа модели нет. Префикс `openai/` в имени модели Groq обозначает семейство открытой модели, а не использование баланса OpenAI.

## Подключение

В серверном `.env` задайте:

```dotenv
AI_PROVIDER=groq
GROQ_API_KEY=your_groq_server_api_key
GROQ_MODEL=openai/gpt-oss-20b
```

Создайте собственный ключ на [Groq Console](https://console.groq.com/keys), используя Free tier. Бесплатный тариф имеет ограничения по запросам и токенам; актуальные значения для аккаунта отображаются в [Limits](https://console.groq.com/docs/rate-limits). Доступность бесплатного тарифа и модели зависит от аккаунта провайдера. Пример выше не является ключом.

OpenAI остаётся доступен через `AI_PROVIDER=openai`, `OPENAI_API_KEY` и `OPENAI_MODEL=gpt-4.1-mini`. Ключи провайдеров не взаимозаменяемы. Приложение не переключается автоматически на платный сервис при ошибке Groq. Неизвестный провайдер отклоняется до отправки секретов. Если AI_PROVIDER отсутствует в старом .env, для обратной совместимости используется OpenAI; новый .env.example предлагает Groq.

После изменения `.env` выполните `php artisan config:clear` и перезапустите локальный `artisan serve`. Ключ хранится только на сервере и не должен попадать в Git, Postman, браузер или фронтенд. Выбранная модель должна поддерживать Responses API и Structured Outputs.

## Запрос и результат

Покупатель отправляет `POST /api/v1/ai/recommendations` с Bearer-токеном Sanctum и JSON:

```json
{
  "budget": 10000000,
  "format": "65",
  "preferences": "Тихая клавиатура для работы, линейные свитчи"
}
```

Деньги указаны целыми тиынами KZT: `10000000` соответствует 100 000 тенге. Пожелания ограничены 1000 символами. Лимит — 10 запросов в минуту на пользователя, включая неудачные запросы. Таймаут внешнего вызова — 30 секунд, соединения — 5 секунд; автоматических платных повторов нет.

Модели передаются только бюджет, формат, пожелания и доступные детали каталога: ID, название, тип, формат, цена, остаток и характеристики. Email, пароль и токен пользователя в payload не включаются. Поэтому в свободном тексте пожеланий также не следует указывать личные данные. Для OpenAI устанавливается `store: false`. Groq не поддерживает этот параметр, поэтому он не передаётся; для GPT-OSS задаётся `reasoning.effort=low`.

Ответ модели запрашивается по строгой JSON Schema: массив `items` с `component_id` и `quantity`, а также `explanation`. Сервер проверяет типы данных, повторяющиеся и выдуманные ID, принадлежность ID переданному каталогу, количества, остатки, комплектность, совместимость и бюджет. После внешнего вызова детали повторно считываются из БД, чтобы учесть изменение каталога за время ожидания. Итог вычисляет сервер из текущих цен.

При успехе ответ `200` содержит `data.items`, `data.explanation`, `data.total` и `data.compatibility`. Сборка автоматически не сохраняется; клиент может предложить пользователю сохранить выбранный состав через API сборок. Наличие деталей при подборе не резервируется: окончательная проверка и списание выполняются при оформлении заказа.

## Коды ошибок

| Код | Причина |
| --- | --- |
| 401 | Не передан действующий токен |
| 403 | Роль не даёт доступа к подбору |
| 422 | Неверные параметры, нет доступных деталей, подбор несовместим или превышает бюджет, каталог изменился |
| 429 | Превышены 10 запросов в минуту |
| 503 | Нет ключа, провайдер недоступен, таймаут, неполный ответ, отказ модели или некорректные данные ответа |

Сырые ошибки провайдера и секреты пользователю не возвращаются.

## Проверка

`php artisan test --filter=RecommendationTest` проверяет настоящий HTTP-контракт приложения с подставленными ответами провайдера (`Http::fake`): корректный ответ, приватность payload, проверку каталога после ожидания, несовместимость, бюджет, наличие, неизвестные и повторяющиеся ID, сетевую ошибку, отказ и неполный JSON, отсутствие ключа, а также ограничение частоты запросов. Эти тесты не расходуют средства API.

Переключение на Groq проверено на контролируемых ответах HTTP: корректный подбор, раздельные ключи, отсутствие неподдерживаемого store, отказ при неизвестном провайдере, ошибка квоты без платного fallback. Реальная успешная генерация Groq требует вашего ключа и отдельного запроса. Диагностический вызов OpenAI ранее вернул credit_balance_exhausted; успешного оплачиваемого подбора не было.

Контракты: [Groq Responses API](https://console.groq.com/docs/responses-api), [Groq Structured Outputs](https://console.groq.com/docs/structured-outputs), [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses).
